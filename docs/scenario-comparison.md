# Сравнение двух сохранённых расчётов

Сравнение показывает, что изменилось между двумя готовыми решениями:
смета сети, подключения ОКС, трассы, врезки и вводы. JSON подходит для
дальнейшей обработки, PDF — для передачи эксперту без веб-интерфейса.
Оба формата создаются из одного представления данных.

Сначала выполняются два обычных расчёта. Затем модуль сравнения только
читает их сохранённые результаты: он не запускает поиск маршрута и
не меняет исходные файлы, задания или смету. Выбирайте варианты явно:
например, `v1` первого задания и `v1` второго. Допускаются base/base и
depth/depth, включая разные варианты одного режима; base/depth отклоняется.

## Пример: появилась запретная зона

В `samples/scenario-comparison/` находятся два входных GeoJSON с четырьмя ОКС
и одинаковый YAML. В `after.geojson` добавлен только один полигон
`scenario-prohibited-1` типа `prohibited_site`, размером 14 × 18 м.
Он пересекает прежний путь к ОКС 2. Все прежние объекты сохранены.

Команды выполняются из корня репозитория после `mvn package`:

```sh
java -jar target/heatnet-1.0.0.jar --spring.profiles.active=cli --input=samples/scenario-comparison/before.geojson --rules=samples/scenario-comparison/rules.yaml --output=before-result.geojson
java -jar target/heatnet-1.0.0.jar --spring.profiles.active=cli --input=samples/scenario-comparison/after.geojson --rules=samples/scenario-comparison/rules.yaml --output=after-result.geojson
java -jar target/heatnet-1.0.0.jar --spring.profiles.active=cli --compare-results --before-input=samples/scenario-comparison/before.geojson --before-result=before-result.geojson --before-variant=v1 --before-rules=samples/scenario-comparison/rules.yaml --after-input=samples/scenario-comparison/after.geojson --after-result=after-result.geojson --after-variant=v1 --after-rules=samples/scenario-comparison/rules.yaml --output=comparison.json
```

Последняя команда создаёт `comparison.json` и `comparison.pdf`. Для сравнения
с учётом глубины замените файлы результатов на `before-result-depth.geojson`
и `after-result-depth.geojson`, варианты — на `d1`, имя выхода — на
`comparison-depth.json`. Входные GeoJSON и YAML остаются теми же.

В PDF схемы до/после имеют единый масштаб. Будущая зона показана контуром
на схеме «до» и заливкой «после»; изменённые части трассы выделены цветом.
Таблицы показывают итоговые показатели и изменившиеся подключения.

Проверенный результат этого примера:

| Показатель | До | После | Изменение |
|---|---:|---:|---:|
| Подключения, v1 и d1 | 4 из 4 | 4 из 4 | Все сохранены |
| Длина сети, v1 и d1 | 324,94 м | 330,04 м | +5,10 м |
| Строительство, v1 | 42 974 655 ₽ | 43 400 658 ₽ | +426 003 ₽ |
| Строительство, d1 | 43 731 975 ₽ | 44 157 978 ₽ | +426 003 ₽ |

В v1/d1 изменился путь ОКС 2: 144,47 → 149,57 м. Врезка, стена ввода
и остальные три пути сохранились. Новый маршрут обходит запретную зону;
для её отступов выполнена отдельная проверка по ДУ. Это проверка конкретного
примера, не новое доказательство соблюдения всех нормативных условий.

## API

Дождитесь статуса `DONE` обоих заданий и передайте их ID и варианты:

```sh
curl -G "http://localhost:8080/api/v1/tracing/comparison" --data-urlencode "before_job_id=ID_ДО" --data-urlencode "before_variant_id=v1" --data-urlencode "after_job_id=ID_ПОСЛЕ" --data-urlencode "after_variant_id=v1" -o comparison.json
curl -G "http://localhost:8080/api/v1/tracing/comparison.pdf" --data-urlencode "before_job_id=ID_ДО" --data-urlencode "before_variant_id=v1" --data-urlencode "after_job_id=ID_ПОСЛЕ" --data-urlencode "after_variant_id=v1" -o comparison.pdf
```

Все четыре параметра обязательны. API получает пути из сохранённых заданий,
а правила — из текущего серверного справочника с YAML каждого задания.
Пути к локальным файлам клиент API не передаёт.

| Случай | Ответ |
|---|---|
| Успешное сравнение | 200, `application/json` или `application/pdf`, attachment |
| Не передан обязательный параметр | 400 |
| Задание не найдено | 404 |
| Задание не DONE, нет нужного результата, неверный вариант, смешанные режимы или противоречивые данные | 409 с объяснением |

Эндпоинты описаны в Swagger. JSON не содержит времени формирования,
поэтому по одним и тем же файлам и эффективным правилам API и CLI дают
одинаковые данные. PDF может различаться служебными метаданными.

## Параметры CLI

| Параметр | Назначение |
|---|---|
| `--compare-results` | Включить режим сравнения |
| `--before-input`, `--after-input` | Исходные GeoJSON двух расчётов |
| `--before-result`, `--after-result` | Сохранённые результаты соответствующего режима |
| `--before-variant`, `--after-variant` | Явные ID вариантов |
| `--output` | Выходной JSON |
| `--pdf-output` | Необязательный путь PDF; по умолчанию рядом с JSON, с расширением `.pdf` |
| `--before-rules`, `--after-rules` | Необязательные YAML каждого расчёта |

Не объединяйте `--compare-results` с `--export-connection`.
Выходы должны отличаться друг от друга и от всех входов, результатов и YAML.
Оба отчёта подготавливаются до замены выходных файлов; две финальные замены
не являются общей файловой транзакцией. Успех — exit 0; некорректные параметры
или противоречивые данные — exit 2; ошибка чтения/записи — exit 1.

## Что означают показатели

Все дельты — **после минус до**. Строительство, штраф за неподключённые ОКС
и итоговая расчётная стоимость показаны отдельно. Более дешёвая сеть с
потерянными подключениями не объявляется улучшением.

ОКС сопоставляются по точному исходному ID: `n:2` — число 2, `s:2` — строка
«2». Добавление/удаление ОКС во входе отделено от потери/восстановления
подключения прежнего ОКС. Неизменённые и оставшиеся неподключёнными объекты
есть в полном JSON; PDF подробно показывает изменившиеся.

Трассы сравниваются по объединённой XY-геометрии в EPSG:32637 с допуском
1 см. Перенумерация, обратная ориентация и разрез прежнего сегмента сами
по себе не означают новую трассу. `added_length_m` / `removed_length_m` —
длины частей вне сантиметрового коридора другой сети. Они отличаются от
сметной длины `new_network_length`, в которой сохранено экспортное округление.

Если путь XY совпадает, дополнительно сравниваются распределённые вдоль него
ДУ, способ прокладки, расход и глубины. Для глубины и пикетажа используется
допуск 1 см, для расхода — 0,000001 т/ч. При разных XY-путях или расхождении
их длины более чем на 1 см такое сопоставление не выполняется:
`segment_attributes` содержит `null` и причину; сами участки обеих сторон
сохранены в `route_segments`. `null` означает отсутствие сопоставления,
а не отсутствие изменений. Неоднозначная внешняя стена также отмечается
как недоступная для сравнения.

Стоимость участков пути ОКС включает общие трубы, но не распределяет их
стоимость между зданиями и не включает камеры и врезки. Это **не цена
индивидуального подключения**; строки ОКС нельзя суммировать в стоимость
всей сети.

## Состав JSON и границы применения

`schema_version=1`; разделы:

- `before`, `after`: вариант, режим, SHA входа/результата/эффективных правил,
  сводные показатели.
- `delta`: изменения итоговых показателей.
- `connections_summary`, `connections`: состояния ОКС, снимки до/после,
  признаки изменений и дельты длины/стоимости пути.
- `network_geometry`: исходные и изменённые XY-линии, длины и допуск.
- `comparison_tolerances`: допуски геометрии, пикетажа, глубины и расхода.
- `input_changes`: ограничения, добавленные или удалённые по типизированному ID.
- `notes`: условия интерпретации.

`input_changes` не является полным сравнением свойств, геометрии существующих
ограничений или YAML. Для проверки происхождения приложите исходные файлы:
их SHA есть в отчёте. Историческая версия встроенного справочника не хранится
в GeoJSON; используйте ту же сборку и YAML, что при расчёте.

Сравнение не доказывает глобальную оптимальность, единственную причину
изменений или нормативную допустимость сети. Проверки целостности сохранённых
данных не заменяют новый инженерный аудит. Новая запретная зона может
перестроить общую сеть, поэтому измениться способны и другие подключения.
