# Публичный стенд HEATNET на VPS

Инструкция разворачивает сервис с PostgreSQL и HTTPS через Caddy.
До публикации нужно проверить выбранный сервер на своих входных наборах.

## 1. Арендовать VPS

Стартовая конфигурация стенда: **Ubuntu 22.04, не менее 4 ГБ ОЗУ,
2 vCPU и 20 ГБ диска**, один расчёт одновременно. Это ориентир для настройки,
а не доказанный минимум для любого набора: память нужна также PostgreSQL,
Caddy, ОС, геометрии и временным файлам. Для конкурсной машины ориентир ТЗ —
16 ГБ ОЗУ. Диск выбирайте с запасом под входы и результаты всех заданий;
автоматического удаления старых заданий нет.

Записать IP-адрес сервера — далее он обозначается `IP`.

## 2. Установить Docker (на сервере, один раз)

```bash
ssh root@IP
curl -fsSL https://get.docker.com | sh
```

## 3. Развернуть сервис

```bash
git clone https://github.com/dmitrywalther/heatnet.git
cd heatnet
# Установить конкретную проверенную версию перед сборкой.
# Для обновления существующего стенда используйте его прежний DOMAIN.
DOMAIN=heatnet.IP-с-дефисами.nip.io docker compose \
    -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build
```

`nip.io` — бесплатный сервис: имя `heatnet.1-2-3-4.nip.io` само
указывает на IP `1.2.3.4`, регистрировать ничего не нужно. Caddy при
первом запросе автоматически выпустит сертификат Let's Encrypt.

Сервис `app` проверяется HTTP-запросом к справочнику правил; Caddy запускается
после успешного healthcheck. PostgreSQL имеет отдельный `pg_isready`.
Проверка состояния и журналов:

```bash
DOMAIN=heatnet.IP-с-дефисами.nip.io docker compose \
    -f docker-compose.yml -f deploy/docker-compose.prod.yml ps
DOMAIN=heatnet.IP-с-дефисами.nip.io docker compose \
    -f docker-compose.yml -f deploy/docker-compose.prod.yml logs --tail=100 app db caddy
```

Проверить полный сценарий: загрузить GeoJSON и YAML, дождаться расчёта,
проверить карту, переключение глубины и скачивание обоих GeoJSON и PDF.
HTTP healthcheck не заменяет эту проверку и не измеряет свободную память.
Адреса:

- `https://heatnet.IP-с-дефисами.nip.io/ui/` — веб-интерфейс;
- `https://.../swagger-ui.html` — API.

## 4. Свой домен (по желанию)

Купить домен (~300 ₽/год), создать A-запись на `IP`, перезапустить
с `DOMAIN=ваш.домен` — сертификат выпустится автоматически.

## Заметки

- Prod-надстройка задаёт `JAVA_OPTS=-Xmx2600m`: такой heap использовался
  для локальных расчётных проверок. Это не лимит всей памяти контейнера и
  не гарантия работы VPS. Базовый Dockerfile/compose сохраняет `-Xmx12g`
  под машину из ТЗ с 16 ГБ ОЗУ. Оба значения можно явно заменить переменной
  `JAVA_OPTS` перед командой `docker compose`.
- `HEATNET_TRACING_WORKERS=1` ограничивает число одновременных заданий;
  `HEATNET_TRACING_QUEUE_CAPACITY=100` задаёт очередь. Увеличивать workers
  следует только после измерения пика памяти нескольких параллельных задач.
  Один расчёт сам выполняет несколько порядков построения параллельно.
- Порт 8080 привязан только к `127.0.0.1`; внешние обращения проходят через
  Caddy на 80/443. PostgreSQL не публикует порт на хосте.
- Spring принимает GeoJSON до 3 GiB, YAML до 1 MiB, весь multipart-запрос до 3100 MiB;
  предел Caddy 4 GB оставляет запас на YAML и обрамление. Возможность
  рассчитать произвольный файл 3 ГБ не подтверждена. Временная загрузка
  использует диск контейнера; итоговые файлы лежат в постоянном `appdata`.
- `pgdata` хранит задания PostgreSQL, `appdata` — входы, правила и результаты,
  `caddy_data` — состояние TLS. Сохраняйте резервную копию обоих первых
  томов вместе. Обновляйте сервис без `down -v`, чтобы не удалить данные.
- Перед обновлением дождитесь завершения текущих расчётов: очередь и
  незавершённая работа не продолжаются автоматически после перезапуска.
  Прежние QUEUED/RUNNING переводятся в ERROR с объяснением. При отказе приёма
  в очередь новый запрос получает HTTP 503, сохранённое задание — ERROR.
  Завершённые задания сохраняются. Поддерживается только один экземпляр
  приложения; несколько реплик с общей БД запускать нельзя.
- Обновление стенда: получить конкретную проверенную версию и повторить
  `up -d --build`, затем проверить состояние и сквозной сценарий.
  **После стоп-кода хакатона стенд не обновлять.**
